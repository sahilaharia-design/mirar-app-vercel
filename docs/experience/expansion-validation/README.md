## Reproduce

Build `npm run visual:build`, serve `dist-review` on a local port, then run the two verification scripts with `MIRAR_EXPANSION_PREVIEW` and `AGENT_BROWSER_BIN`. The inherited sample harness can point to the same preview; it routes to simulated entry there, rather than signing into the real app. Do not mistake that callback check for authentication delivery.

## Limits and gates

- Hosted review uses simulated sign-in and in-memory runtime storage; it does not verify real signup or a magic-link return.
- Historical records are explicitly fictional. A reading is shown only if supplied by Claude’s repaired model; no state or continuity is manufactured by the UI.
- The two pilots are authored candidates, not production reps, and never write into runtime receipts or the Mirror. Claude must reconcile their exact inputs, observation meaning, optional intention and catalogue/version policy before authenticated behavior is connected.
- Landing study layers are read-only and fictional; they collect no feedback.
- Pending human invitations from the earlier sample remain pending and version-specific, not results. No efficacy, retention or benefit finding is claimed.
- Native assistive technology, Hindi/Gujarati type parity and specialist legal/safety review remain separate requirements.
- Public mirar.life, auth, production routing and release remain Claude-owned and unchanged.
