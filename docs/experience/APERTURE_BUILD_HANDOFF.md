## What is implemented

One Mirar world: an actual source-defined reflective opening, live questions outside masks, exact chosen responses, a separate reading surface, and room for uncertainty. It is not a generic oval component library. The canonical mark and wordmark files are unchanged and verified against the supplied originals. The original graphic uses the actual mark alpha; annotation planes are independent elements. No image was traced/recoloured, no stock imagery, ambient loop, progress-ring fill or per-option logo repetition.

- **Landing:** `landing/` builds a standalone static website using the same `DiscoverExperience` as the app. Public root positioning is emotional fitness through practice, no score or streak, no 28-day programme, diagnostic email or guaranteed daily insight. Real `foc_settle` sample before auth, sample-specific integration, selectable capacity explanation, optional **inert** fictional study, point-of-use retention and existing legal destinations. The mobile hero includes the reflective graphic before the supporting copy; desktop gives it a separate large plane.
- **Entry:** existing ordinary email/sending/sent/expired/error/retry presentation and callbacks retained; same fonts/material foundation. No authentication protocol changes.
- **Onboarding:** permission quiz removed. Brief, non-diagnostic arrival with a direct first-rep/Today route; no new preference or extra setup question.
- **Today:** native graphic boundary, supported new/available/resume/done states, optional capacity metadata, real current commitment and supplied continuity. No synthetic remembered sentence, day unlock or urgency. The continuity slot remains unused unless Claude supplies it.
- **Inner Rep:** unchanged engine sequencing and exact prompts/options, existing compare/list/words/context/check-in/timeframe controls. Standard semantic controls, no drag-only input or mechanical novelty. Current auto-advance policy preserved while D4 is unresolved. New Reframe/sort/pause families are not presented as implemented.
- **Integration:** `IntegrationMoment` accepts `Receipt | null`; displays exact step questions/responses and the actual chosen commitment/date. Unknown, explicit absence/non-action, ordinary response, multi-response and chosen intention have distinct releases. Generic “notice once later” paragraph removed. Immediate-session fallback uses public `nextStep` only; reload relies on Claude's supplied `receipt()`.
- **Honest Mirror:** provenance counts visible without opening disclosure. Equal feedback remains. Successful feedback replaces the active interpretation with a specific event acknowledgement; failure leaves reading/controls retryable and does not claim success. Partly reasons remain exact/equal; Skip ends the optional correction rather than re-offering it. Successful reason submission visibly acknowledged. Optional note privacy wording, clear-on-Continue/Skip and existing safety behavior preserved. No guaranteed date promise inferred from cooldown.
- **The Mirror:** accepts typed `MirrorModel`, plus existing factual props for current app compatibility. Empty/sparse factual views, alphabetical practice facts, neutral carrying and collapsed selected-response provenance. A future approved historical-reading view is source-separated and includes supplied unknown/shift statements; it is **explicitly gated off by default** pending Claude's remaining eligibility repairs. The renderer does not calculate eligibility or supporting evidence.
- **Me / Privacy:** existing quiet product behavior and account callbacks remain, within the shared shell. No new deletion/sync promise or replacement legal text.
- **Review:** `review/ExperienceReview.tsx` runs a complete simulated-sign-in journey through the **real** runtime with memory-only storage, supplies real `receipt()`/`mirror()` views and refreshes them on callbacks. No Supabase, actual email or authenticated production writes. Synthetic returning scenarios were generated by Claude's existing review builder, labelled explicitly and imported only by review entry points. Component fixtures label their fictional insight and do not attach one after an unknown completion.

## Local review and build instructions

Existing dependencies only; no framework upgrade or new package. Root Expo `build` and `vercel-build` remain unchanged.

```sh
npm run landing:dev
# http://127.0.0.1:5177/
npm run visual:review
# http://127.0.0.1:5174/?experience=discover
npm run landing:review-build
npm run visual:build
npm run typecheck
```

Standalone output: `landing/dist/`. App build: existing Expo export. Review output: `dist-review/`, **never the production app/landing output**. An unconfigured local landing CTA shows a pending-configuration message instead of visiting an invented auth path.

After Claude confirms the complete destination:

```sh
MIRAR_APP_ENTRY_URL="$CLAUDE_VERIFIED_APP_ENTRY_URL" MIRAR_DESTINATIONS_VERIFIED=1 npm run landing:build
```

`landing:build` intentionally rejects missing/unverified configuration or non-HTTPS entry. It does not alter auth redirects or Vercel. `MIRAR_DESTINATIONS_VERIFIED` is Claude's release assertion, not a user permission flow.

Suggested local cases:

- `?experience=discover`, `entry`, `intro`, `today`, `mirror`, `me`, `privacy` on port 5174.
- `?experience=today&scenario=compare`, `words`, `followup`, `timeframe`, `commitment_check`, `thread_check`, `lens`, `resolution`, `open_question`.
- `?case=mirror&feedbackFail=1` / `correctionFail=1`, `?case=retry`: labelled component fixtures with intentionally failing first callbacks.

`review/aperture-scenarios.json` is explicit synthetic review material generated through the existing runtime builder. Dates are generation-day fixtures, not customer history; regenerate for later-date QA. No production adapter imports it.
